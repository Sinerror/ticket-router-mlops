# Что писать в резюме

Все цифры — из прогонов `make simulate`, `make benchmark` и docker-стенда (см. README). Раздел: «Собственные проекты», с пометкой о данных.

> **Жизненный цикл модели маршрутизации обращений** (github.com/…)
>
> - Построил цикл переобучения rubert-tiny2: DVC → PyTorch → ворота качества → MLflow Model Registry → shadow и canary → мониторинг дрейфа (Evidently) → переобучение по алерту (Airflow).
> - На симуляции сдвига данных (новая тема и разговорная лексика) дрейф обнаруживается без меток за 7 «дней», с 0 ложных алертов за 90 спокойных дней. Качество восстанавливается до macro-F1 0.992 против 0.78 без цикла.
> - На docker-стенде путь от алерта дрейфа до новой модели в production (обучение на GPU, ворота, shadow, canary, promote) занимает 3 мин 50 с без участия человека. Откат на прошлую версию — 1.9 с.
> - Ворота качества (macro-F1 и F1 по классам против production) остановили 3 из 3 релизов на систематически испорченной разметке и пропустили чистую.
> - ONNX Runtime int8 ускорил инференс на CPU в 3.2 раза (p50 2.28 → 0.71 мс) без потери macro-F1, размер модели 111 → 28 МБ.
>
> Данные: публичный датасет обращений (Bitext, RU), «месяцы» симулированы.

**Ключевые навыки:** MLflow, Airflow, DVC, PyTorch, ONNX Runtime, Evidently, FastAPI, Prometheus/Grafana, Docker Compose, GitHub Actions (CI/CD для ML).

Пункт «вместо ручного процесса» из исходной спеки не включён: время ручного процесса не измерялось.
